# Armenia Retail ERP

Տեղային փորձնական տարբերակ մեկ սուպերմարկետի համար։ Կարելի է ստեղծել ապրանք, գրանցել պահեստի մուտք, կատարել վաճառք և նույն վաճառքից մասնակի վերադարձ։ POS զամբյուղով մեկ վաճառքում կարելի է համատեղ գրանցել մի քանի ապրանք, այդ թվում՝ Data Matrix-ով դրոշմավորված միավորներ։

## Տեղային գործարկում Windows-ում

Պահանջվում են .NET 10 SDK, SQL Server և SQL Server Management Studio կամ sqlcmd։

1. Ստեղծիր դատարկ փորձնական SQL Server բազա, օրինակ՝ `ArmeniaRetailERP_Dev`։
2. Բացիր `src/Retail.Api/Database` պանակը և նույն բազայի վրա գործարկիր բացակայող միգրացիաները համարների աճման կարգով։ Նոր բազայի համար հերթականությունն է՝ `001-initial.sql` → `002-product-model-editor.sql` → `003-models.sql` → `004-relations.sql` → `005-product-identifiers.sql` → `006-marking-ledger.sql` → `007-pos-receipts.sql`։ Առաջին փուլից թարմացնելիս սկսիր 003-ից, իսկ երկրորդ փուլից՝ 005-ից։
3. Մինչ API-ն գործարկելը նույն PowerShell պատուհանում սահմանիր երեք տարբեր փորձնական բանալի։ Պահիր դրանք տեղային միջավայրում։

```powershell
$env:RetailAccess__AdminToken = [guid]::NewGuid().ToString('N') + [guid]::NewGuid().ToString('N')
$env:RetailAccess__ManagerToken = [guid]::NewGuid().ToString('N') + [guid]::NewGuid().ToString('N')
$env:RetailAccess__CashierToken = [guid]::NewGuid().ToString('N') + [guid]::NewGuid().ToString('N')
```

Նույն պատուհանում նախագծի պանակից գործարկիր API-ն։ Օրինակը Windows-ի տեղային SQLEXPRESS-ի համար է։ Այլ instance-ի դեպքում փոխիր Server արժեքը։

```powershell
$env:ConnectionStrings__Retail = 'Server=localhost\SQLEXPRESS;Database=ArmeniaRetailERP_Dev;Integrated Security=True;Encrypt=True;TrustServerCertificate=True'
dotnet run --project src/Retail.Api --no-launch-profile --urls http://localhost:5080
```

TrustServerCertificate պարամետրը նախատեսված է այստեղ նշված տեղային փորձնական բազայի համար։

4. Երկրորդ PowerShell պատուհանում գործարկիր Web Admin-ը և բացիր [http://localhost:5081](http://localhost:5081)։

```powershell
$env:RetailApi__BaseUrl = 'http://localhost:5080'
dotnet run --project src/Retail.Admin --no-launch-profile --urls http://localhost:5081
```

5. Python 3-ով գործարկիր API փորձարկումը։

```powershell
python tests/smoke.py http://localhost:5080
```

Փորձարկումը ստեղծում է նոր ապրանք 450 AMD գնով, մուտքագրում 10 միավոր, վաճառում 3 և վերադարձնում 1։ Վերջնական մնացորդը պետք է լինի 8։ Ստուգվում են նաև կրկնակի ուղարկումը, նույն հարցման ID-ով տարբեր տվյալների ուղարկումը, մնացորդից ավելի վաճառքի և վաճառված քանակից ավելի վերադարձի մերժումը։ Փորձնական ապրանքն ու գործարքները մնում են բազայում։

## Մոդելի և ձևի խմբագրիչ

**Ապրանքներ** մոդելի դաշտը կարող է լինել տեքստ, ամբողջ թիվ, այո/ոչ կամ հղում մեկ այլ մոդելի գրառմանը։ Դաշտի նկարագրությունը, ձևում դիրքը, դերային իրավունքները և ապրանքի արժեքը պահվում են SQL Server-ում։

1. Web Admin-ում ընտրիր «Մոդելների խմբագրիչ» և մուտքագրիր Admin բանալին։ Նույն դիտարկիչով վերադառնալիս մուտքը պահպանվում է մինչև 7 օր։ «Դուրս գալ» կոճակը կամ Web Admin-ի սերվերի վերագործարկումն ավարտում է աշխատաշրջանը։
2. Ստեղծիր դաշտ և սահմանիր դիրքը։ Ապրանքի ձևում հայտնվում են տեղադրված և տվյալ դերին հասանելի դաշտերը։
3. Admin-ը կարող է առանձին միացնել մենեջերի՝ նոր դաշտեր ստեղծելու և ձևում տեղադրելու իրավունքը, ինչպես նաև առանձին դաշտի արժեքը կարդալու և փոխելու իրավունքը։
4. Manager բանալիով բացիր գոյություն ունեցող ապրանքի ձևը և փորձիր լրացնել թույլատրված դաշտը։ Խմբագրիչի իրավունքը կարելի է հետ վերցնել անկախ դաշտի արժեքի իրավունքից։

### Օրինակ՝ ապրանքանիշի ընտրություն

1. Admin բանալիով մտիր խմբագրիչ։ Ստեղծիր մոդել՝ `brand` կոդով և «Ապրանքանիշ» անունով։
2. Ընտրիր նոր մոդելը և ավելացրու երկու գրառում, օրինակ՝ «Արարատ» և «Նաիրի»։
3. Ապրանքի վրա ստեղծիր `brand_id` դաշտը՝ «Ապրանքանիշ» անունով։ Ընտրիր «Կապ մոդելի հետ» տեսակը և «Կապակցված մոդել» դաշտում նշիր `brand`։ Սահմանիր դաշտի դիրքը և տեղադրիր այն ձևում։
4. Մենեջերին տուր այս դաշտը դիտելու և լրացնելու իրավունք։ Manager բանալիով բացիր ապրանքը, ընտրիր «Արարատ» և պահպանիր։ Կրկին բացիր ապրանքի ձևը՝ պահպանված ընտրությունը տեսնելու համար։ Դաշտում երևում է անունը, իսկ ապրանքի հետ պահվում է գրառման նույնացուցիչը։
5. Հետ վերցրու դաշտի իրավունքը։ Հաջորդ հարցումից սկսած մենեջերը կորցնում է և՛ ընտրացանկի, և՛ պահպանված արժեքի հասանելիությունը։ Admin-ը շարունակում է տեսնել արդեն կատարված ընտրությունը։

Նոր մոդելը բաղկացած է մոդելի կոդից, ցուցադրվող անունից և անվանված գրառումներից։ Admin-ը ստեղծում է մոդելները, գրառումները և դրանց հղվող դաշտերը։ Մենեջերին կարելի է տալ ապրանքի կոնկրետ դաշտում գրառում ընտրելու իրավունք՝ անկախ ձևը խմբագրելու իրավունքից։ Այս փուլի UI-ն աջակցում է մոդելների ու գրառումների ստեղծմանը և դրանց ցանկի դիտմանը։

### API-ի փորձարկում

Իրավունքները ստուգելու համար գործարկիր ստորև նշված հրամանը նույն երեք միջավայրային փոփոխականներով և առանձին փորձնական բազայի վրա։ Փորձարկումները ստեղծում են փորձնական ապրանքներ, մոդելներ, գրառումներ և դաշտեր։

```powershell
python tests/model_editor.py http://localhost:5080
python tests/model_relations.py http://localhost:5080
```

## Շտրիխկոդ և առանձին միավորների դրոշմավորում

Ապրանքային շտրիխկոդով փնտրիր ապրանքի քարտը։ GTIN-ը նույնացնում է տվյալ տեսակի ապրանքը, ԱՏԳ ԱԱ դաշտը պահում է ապրանքի դասակարգման տասը նիշը, իսկ GS1 Data Matrix-ի սերիական համարը՝ կոնկրետ միավորը։ Նույն ապրանքից երկու հատ մուտքագրելիս երկու տարբեր միավորային կոդ է պետք։ GTIN-ն ու ԱՏԳ ԱԱ-ն մուտքագրիր որպես տեքստ՝ պահպանելով սկզբի զրոները։

Ապրանքի նույնացուցիչները փոխելու իրավունք ունի Admin-ը։ Միավորային դրոշմավորումը միացրու նոր ապրանքի վրա կամ այնպիսի քարտում, որի մնացորդը զրո է և նախկին չդրոշմավորված վաճառքից վերադարձի ենթակա միավորներ չկան։ Եթե կան դեռ վերադարձվող վաճառքներ, դրոշմավորվող խմբաքանակի համար բացիր առանձին ապրանք։ Առաջին դրոշմավորված մուտքից հետո տվյալ քարտի GTIN-ը և դրոշմավորման ռեժիմը ֆիքսվում են։

### Փորձնական ընդունում, վաճառք և վերադարձ

1. Գլխավոր էջում ստեղծիր նոր ապրանք՝ 450 դրամ գնով։ Մինչև առաջին մուտքը ապրանքացանկում սեղմիր ապրանքի անվան վրա։ Խմբագրիչում միացիր Admin բանալիով և բացված ապրանքի «Ապրանքի նույնացուցիչներ» հատվածում լրացրու տվյալները։ Փորձնական քարտի համար կարող ես օգտագործել `4006381333931` շտրիխկոդը և `04006381333931` GTIN-ը։ Իրական ապրանքի դեպքում օգտագործիր տվյալ փաթեթավորման նույնացուցիչներն ու համապատասխան դասակարգման կոդը։ Միացրու միավորային դրոշմավորումը և պահպանիր։
2. Ընտրիր ապրանքի մուտք։ Գլխավոր էջի «Ապրանքի շտրիխկոդ» դաշտում սկանավորիր կոդը և սեղմիր Enter կամ «Գտնել ապրանքը»։ Նշիր երկու միավոր և Data Matrix դաշտում գրանցիր երկու փաթեթների կոդերը՝ ամեն մեկը նոր տողով։ Փորձնական տողեր են `010400638133393121DEMO0001` և `010400638133393121DEMO0002`։ Ակնկալվող մնացորդը 2 է։
3. Բացիր POS-ը (`/pos`), ավելացրու նույն ապրանքից մեկ միավոր՝ սկանավորելով առաջին միավորի ամբողջ կոդը։ Զամբյուղին ավելացրու նաև մնացորդ ունեցող սովորական ապրանք և հաստատիր վաճառքը։ Դրոշմավորված տողի գումարը 450 դրամ է, մնացորդը՝ 1։ Պահպանիր այդ տողի ID-ն՝ վերադարձի համար։
4. Վերադարձում ընտրիր հենց այդ տողի ID-ն, նշիր քանակը՝ 1 և սկանավորիր վերադարձվող միավորը։ Մնացորդը նորից 2 է։ Երկրորդ միավորն այս վաճառքով չի վաճառվել․ դրա կոդով վերադարձը պետք է մերժվի։

Օգտագործիր GS1 Data Matrix կարդացող 2D սկաներ։ Փորձիր մեկ պիտակ՝ ստուգելու, որ սկաները ամբողջությամբ փոխանցում է GTIN-ը (01), սերիական համարը (21) և հաջորդող տվյալներում առկա խմբային բաժանիչը (ASCII 29)։ Սկաների ստեղնաշարային ռեժիմում միջերեսը ճանաչում է նաև Ctrl+] բաժանիչը։ Յուրաքանչյուր կոդից հետո Enter-ը սկսում է հաջորդ տողը։ Պահպանիր սերիական համարի տառերի ռեգիստրը։ Գրանցման պահին ծրագիրը համեմատում է կոդի GTIN-ը ապրանքի GTIN-ի հետ և յուրաքանչյուր ամբողջ միավորի համար պահանջում է մեկ կոդ։ Մուտքի, վաճառքի ու վերադարձի ժամանակ օգտագործիր նույն ամբողջական սկանավորումը։

API-ի փորձարկումն աշխատեցրու առանձին փորձնական բազայի վրա՝ API-ի նույն փորձնական դերային բանալիներով։

```powershell
python tests/test_marking.py http://localhost:5080
python tests/test_pos_cart.py http://localhost:5080
```

Դրոշմավորման մատյանը տվյալները պահում է տեղային SQL Server-ում։ Պետական համակարգի հետ փոխանակումը, դրոշմանիշի իսկության արտաքին ստուգումը և ՀԴՄ կտրոնի թողարկումը առանձին ինտեգրացիաներ են։ Փորձնական կարգավորումը և դրա սահմանները նկարագրված են [ՀՀ ապրանքների դրոշմավորման նշումներում](docs/product-marking-hy.md)։

## Թողարկման սահմանները

Այս փաթեթը տեղային մշակման և փորձարկման համար է։ Խմբագրիչի և հատուկ դաշտերի նոր API-ները ստուգում են դերը սերվերում՝ ըստ փորձնական բանալու։ Նախորդ ապրանքային, պահեստային և վաճառքի API-ները շարունակում են աշխատել Prototype 01-ի կանոններով և դեռ չունեն օգտատերերի մուտք կամ դերային պաշտպանություն։ Արտադրական տեղակայման համար պահանջվում է ամբողջ համակարգի օգտատերերի նույնականացում և հասանելիության կառավարում։
